# 财务列表页面接口审查与优化记录

审查日期：2026-04-26

## 页面与接口

前端页面：`/finance`，复用 `OrderListBase` 的 `finance` 模式。

后端接口：

| 接口 | 用途 |
| --- | --- |
| `GET /orders?is_finished=true` | 财务列表分页数据 |
| `GET /finance/orders/summary` | 财务汇总行 |
| `GET /finance/orders/export` | 财务 Excel 下载 |
| `GET /finance/orders/{order_id}` | 财务详情 |
| `PATCH /finance/orders/{order_id}/status` | 回款/返点状态 |
| `POST /finance/orders/{order_id}/return` | 退回未完成 |

本轮未修改数据库字段，未修改前端布局样式。

## 权限结论

财务域继续以 `权限.txt` 为准：`super_admin/manager/finance` 可写；`market` 只读；`sales` 禁止访问 `/finance/*`。

| 角色 | 财务列表/汇总/详情 | 下载 | 回款/返点/退回 |
| --- | --- | --- | --- |
| `super_admin` | 全量 | 允许 | 允许 |
| `manager` | 所辖团队 | 允许，限所辖团队 | 允许，限所辖团队 |
| `finance` | 单团队 | 允许，限单团队 | 允许，限单团队 |
| `market` | 单团队只读 | 禁止 | 禁止 |
| `sales` | 禁止 `/finance/*` | 禁止 | 禁止 |

## 已发现问题与处理

| 编号 | 问题 | 风险 | 处理 |
| --- | --- | --- | --- |
| FIN-001 | 回款/返点切换、退回未完成复用财务详情加载 | 只改状态却加载客户、渠道、订单信息、图片等关系，SQL 和对象分配过重 | 新增 `_load_finance_order_for_status_write`，状态写入只加载订单实体本身 |
| FIN-002 | 团队 ACL 原先需要先查订单再查业务员团队 | 经理/财务/市场写入路径多一次数据库往返，越权请求也浪费查询 | `_ensure_finance_order_access` 合并为单条 ACL 探针：订单状态和团队命中一起判断 |
| FIN-003 | 财务汇总和列表是两个独立请求 | 首屏会有列表 + 汇总两次查询 | 保留前端现有布局和交互；后端汇总保持投影聚合，前端已有请求取消/去重逻辑 |
| FIN-004 | 财务角色虽被前端禁入普通订单页，但后端 `/orders` 读接口仍可看本团队未完成订单 | 直接访问 `/orders/unfinished` 或 `/orders/{id}` 可能越过财务页边界 | 财务角色在 `/orders` 列表和详情只允许已完成订单；未完成列表 0 SQL 拒绝，未完成详情 1 SQL 拒绝 |

## 残余风险

1. 财务导出仍会一次性生成完整 HTML Excel 字节流；当前本地 2859 条完成单可接受。若生产数据量显著增加，应改为分批游标读取并流式输出。
2. 财务详情需要完整订单、图片和业务关系，SQL 数高于普通状态写入；这是页面详情所需，不应用于列表或开关类写入。
