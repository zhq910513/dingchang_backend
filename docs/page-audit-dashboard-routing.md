# Dashboard 与前端路由权限审查记录

审查日期：2026-04-26

## 页面范围

前端页面：`/` Dashboard 容器、侧边栏、移动端底部导航、路由守卫。

后端关联：本页本身不直接查询业务数据，安全边界必须由各业务接口兜底。

本轮未修改前端布局样式。

## 权限结论

Dashboard 菜单是体验层权限，不是安全边界。当前后端已经按页面专项完成兜底：

| 入口 | 前端表现 | 后端兜底 |
| --- | --- | --- |
| `/users` | 仅 `super_admin/manager` 可点 | `/users` 后端拒绝 `sales/finance/market` |
| `/orders/*` | `finance` 菜单禁入，`market` 只读 | `/orders` 财务只可读已完成订单；写入拒绝 `finance/market`，`finance` 仅可走 related 图片受限路径 |
| `/finance/*` | `sales` 菜单禁入 | `/finance/*` 后端拒绝 `sales`，`market` 只读 |
| `/customers`、`/channels` | 所有已登录角色可进 | 后端写权限按角色和创建人收口 |
| `/ai-assistant` | 所有已知角色可进 | 后端会话按用户隔离，订单/OCR 数据继承订单域 ACL |

## 已发现问题与处理

| 编号 | 问题 | 风险 | 处理 |
| --- | --- | --- | --- |
| ROUTE-001 | 前端 `router.beforeEach` 只校验登录，不做角色级重定向 | 直接输入 URL 可能进入页面并触发接口 | 保留现状，不改布局；后端各域已兜底，越权请求不会返回数据 |
| ROUTE-002 | 财务菜单禁入普通订单页，但后端普通订单读接口曾允许财务读取未完成订单 | 前端禁入不能防直接调用接口 | 已在订单域收口：财务普通订单列表/详情只允许已完成订单 |
| ROUTE-003 | AI 助手菜单与后端权限函数曾不一致 | 入口口径漂移 | 已在 AI 助手专项收口：已知角色可进，业务数据按 ACL |

## 残余风险

1. 前端路由守卫仍不是统一能力矩阵，菜单逻辑散落在 Dashboard 和页面内按钮。若后续允许修改前端权限架构，应抽出 `canAccessRoute/canUseAction` 能力模块，但不能替代后端鉴权。
2. `sessionStorage` 中的角色只用于前端体验展示，不能作为安全来源；后端继续以 `X-Session-Token` 解析出的真实用户角色为准。
