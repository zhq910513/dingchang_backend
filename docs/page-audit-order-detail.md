# 页面审查：订单详情 / 财务详情
更新时间：2026-04-26

本页审查范围：`/orders/:id`、`/finance/orders/:id`，以及订单详情保存、完成/退回、财务备用图、财务状态更新相关接口。

## 权限边界

| 角色 | 订单详情 | 编辑订单 | 财务详情 |
| --- | --- | --- | --- |
| `super_admin` | 全量可读 | 可编辑，含已完成订单 | 全量可读，可写财务状态 |
| `manager` | 辖区团队可读 | 可编辑辖区订单，含已完成订单 | 辖区可读，可写财务状态 |
| `sales` | 只读/写自己的订单 | 未完成自己的订单可编辑；不能退回已完成订单 | 禁止 |
| `finance` | 后端可读单团队订单；前端订单模块禁入 | 普通订单字段禁止写，仅可通过受限 finalize 维护 `related` 备用图 | 单团队可读，可写回款/返点/退回 |
| `market` | 单团队可读 | 禁止写订单 | 单团队只读 |

## 已发现问题与处理状态

| 编号 | 问题 | 风险 | 处理状态 |
| --- | --- | --- | --- |
| ORDER-DETAIL-001 | 订单详情旧链路先加载完整订单/图片，再做 ACL | 越权请求会触发重对象加载；安全姿势不够好 | 已处理：先轻量读取 `salesperson_id` 做 ACL，通过后再加载详情 |
| ORDER-DETAIL-002 | ORM 模型关系默认 `lazy=selectin`，详情查询会自动加载大量未使用关系 | 单个详情请求 SQL 数膨胀 | 已处理：详情/更新/状态/财务详情查询使用 `lazyload("*")`，再白名单加载需要的关系 |
| ORDER-DETAIL-003 | 财务详情旧链路先加载完整订单，再判断是否已完成/是否跨团队 | 越权或非完成订单浪费查询 | 已处理：财务详情先轻量校验 `is_finished + salesperson_id + team` |
| ORDER-DETAIL-004 | 财务详情加载了 `salesperson.parent`，但 `OrderOut` 不输出这些字段 | 无效关系加载 | 已处理：财务详情移除该关系；导出仍保留，因为 Excel 需要经理/团队 |

## 已实施优化

1. `app/api/v1/orders.py`：`_load_order_out` 改为 ACL-first，越权请求不再加载图片和详情关系。
2. `app/api/v1/orders.py`：订单详情、finalize、更新、状态更新的 `select(Order)` 增加 `lazyload("*")`，避免默认关系树自动补载。
3. `app/api/v1/finance.py`：财务详情改为先轻量校验完成状态和团队范围，再加载详情。
4. `app/api/v1/finance.py`：财务详情和导出实体加载使用 `lazyload("*")`；财务详情移除不需要的业务员父级加载。

## 自检结果

1. 编译检查通过：`python -m py_compile app/api/v1/orders.py app/api/v1/finance.py`。
2. 普通详情 `super_admin`：32 条 SQL 降至 7 条，约 82.17ms 降至 27.75ms。
3. 普通详情 `sales` 访问自己的订单：32 条 SQL 降至 7 条，约 63.78ms 降至 19.04ms。
4. 普通详情 `sales` 越权访问他人订单：32 条 SQL 降至 1 条，约 49.93ms 降至 1.84ms，返回 403。
5. 财务详情 `finance` 可见订单：约 8 条 SQL，约 24.92ms。
6. 财务详情 `finance` 跨团队订单：2 条轻量 SQL，返回 403。

## 残余风险

详情页图片 URL 当前依赖进程内 45 分钟展示 URL 缓存；多进程部署时各进程缓存独立，这是可接受的性能缓存，不作为权限缓存使用。后续如果图片数量显著增长，应考虑详情接口分页/懒加载图片，但当前页面布局不在本轮调整范围内。
